# WakeUp — 버스 하차 알림 개발 계획 (웹앱 + 개인 서버)

## 1. 목표
- 시내버스 탑승 중 **목적지 1~2정거장 전**에 iPhone 잠금화면 푸시 알림.
- 시간 기반이 아닌 **GPS 기반**: 내가 탄 **버스 차량의 GPS 위치**(공공 버스위치 API)로 판정.
- 폰은 백그라운드 위치 수집 없음. 서버의 위치 조회도 **트립 중에만**, 도착 시 자동 중단.
- App Store·Mac·유료 개발자 계정 없이 사용.

## 2. 구성
```
[iPhone: 홈 화면 웹앱(PWA)]
   │ HTTPS (Tailscale Funnel)
   ▼
[노트북 서버: Node.js]
   ├─ TAGO API 조회 (노선/정류장/버스위치)
   ├─ SQLite (캐시, 트립, 푸시 구독)
   └─ Web Push 발송 ──► Apple 푸시 서버 ──► iPhone 잠금화면
```

| 항목 | 선택 |
|---|---|
| 클라이언트 | PWA (TypeScript, Vite, 가벼운 UI 라이브러리 또는 Vanilla) |
| 서버 | Node.js + TypeScript, Fastify |
| 저장 | SQLite (better-sqlite3) |
| 푸시 | Web Push (VAPID, `web-push` 라이브러리) |
| 외부 접속 | Tailscale Funnel (고정 HTTPS 주소, 무료) |
| 프로세스 관리 | pm2 (자동 재시작, 부팅 시 자동 실행) |

## 3. 사용자 흐름
1. (최초 1회) Safari로 접속 → 공유 > **홈 화면에 추가** → 홈 화면 앱에서 알림 허용.
2. 노선 검색 → 탑승·목적지 정류장 선택 (또는 즐겨찾기) → 알림 시점 1/2정거장 전 선택.
3. 버스에 탄 뒤 **"탑승했어요"** 버튼 → 폰 GPS 1회 측정 → 서버가 탑승 차량 식별.
4. 앱을 닫아도 됨. 서버가 차량 위치 추적.
5. 목적지 N정거장 전 도달 → 푸시 알림. 목적지 도달 → 추적 종료, 종료 푸시.

## 4. 데이터 소스
- **국토교통부 TAGO API** (공공데이터포털)
  - 버스노선정보: 노선 검색, 노선별 경유 정류소 목록(`nodeid`, `nodeord`, 좌표)
  - 버스위치정보: 노선별 운행 차량 목록(`vehicleno`, `nodeord`, `gpslati/gpslong`)
- 서울은 TAGO 미제공 가능 → **서울시 버스위치정보 API** 어댑터 추가 (지역 확정 후 결정).
- API 키는 서버 `.env`에만 저장 (git 제외). 클라이언트에 노출 안 함.

### 4.1 노선/정류장 데이터 갱신
- 즐겨찾기·트립은 순번이 아닌 **정류장 ID(`nodeid`) + 노선ID**로 참조. 순번은 최신 목록에서 재계산.
- **트립 시작 시 1회만**, 캐시가 3일 이상 지난 경우에만 해당 노선 조회. 실패 시 캐시 사용.
- 정류장 ID가 새 목록에 없으면 같은 이름 또는 200m 이내 정류장으로 자동 매칭 후 1회 확인 요청. 후보 없으면 "확인 필요" 표시.
- 응답 검증(정류장 0개, 좌표 이상, 순번 누락) 실패 시 기존 캐시 유지.

## 5. 탑승 차량 식별
1. "탑승했어요" 시 폰 GPS 1회 측정 (앱이 화면에 떠 있으므로 가능, 정확도 100m 이하일 때까지 최대 10초).
2. 서버가 해당 노선 운행 차량 목록 조회 → 폰 위치와 가장 가까운 차량 선택.
   - 조건: 거리 ≤ 300m, `nodeord`가 탑승 정류장 순번 ±1 이내.
3. 후보가 2대 이상이거나 없으면 차량번호 목록을 보여주고 사용자가 선택 (차량번호는 버스 내부 표시).
4. 30초 후 재조회해 선택한 차량이 목적지 방향으로 진행 중인지 확인. 아니면 재선택 푸시.

## 6. 추적 및 알림 판정 (서버)
- 트립별 상태머신: `Identifying → Tracking → Alerted → Done`
- 남은 정류장 수에 따라 **조회 간격 조절** (원래 GPS 정밀도 단계 전환과 같은 개념):

| 남은 정류장 (목적지까지) | 조회 간격 |
|---|---|
| > N + 5 | 60초 |
| N + 1 ~ N + 5 | 20초 |
| ≤ N | 알림 후 20초 (도착 감지용) |

- 알림 조건: 차량 `nodeord ≥ 목적지 순번 − N` → 1회 푸시.
- `nodeord`가 "직전 통과 정류장"인지 "다음 정류장"인지 M1에서 실측해 오프셋 확정.
- 차량 좌표가 알림 정류장 반경 150m 이내 진입 시에도 알림 (`nodeord` 갱신 지연 대비).

## 7. 자동 종료 (위치 조회 중단)
- 차량 `nodeord ≥ 목적지 순번` (도착)
- 사용자가 알림 또는 앱에서 "종료"
- 차량이 3회 연속 목록에서 사라짐 (운행 종료/데이터 끊김) → "추적 끊김" 푸시 후 종료
- 최대 3시간 경과

종료 시 트립의 폴링 타이머 해제. 진행 중 트립이 없으면 서버는 외부 API를 전혀 호출하지 않음.

## 8. 푸시 알림
- iOS 16.4 이상, **홈 화면에 추가한 웹앱에서만** 동작. 알림 권한은 버튼 탭으로 요청.
- 서버 재시작에도 유지되도록 푸시 구독 정보를 SQLite에 저장.
- 알림 내용: "다음 정류장 ○○ — 2정거장 뒤 하차". 클릭 시 앱 트립 화면으로 이동.
- 구독 만료(HTTP 404/410) 감지 시 앱 실행 때 재구독.
- 트립 시작 시 "추적 시작" 테스트 푸시를 보내 수신 가능 여부를 바로 확인.

## 9. API 호출량
- TAGO 개발계정 한도: 기능별 일 1,000회 (공공데이터포털 기준, 신청 시 확인).
- 30분 트립 ≈ 40~60회 → 하루 여러 번 타도 충분. 부족하면 운영계정 신청.

## 10. 노트북 서버 운영
| 항목 | 대응 |
|---|---|
| 밖에서(LTE) 접속 | Tailscale Funnel로 `https://<기기명>.<tailnet>.ts.net` 고정 주소. PWA·푸시에 필요한 HTTPS 충족 |
| 덮개 닫음/절전 | 전원 연결 시 절전 끄기, 덮개 닫아도 동작 유지로 설정 |
| 재부팅/크래시 | pm2 자동 재시작 + 부팅 시 자동 실행 |
| 공개 주소 보안 | 1인용 비밀 토큰(최초 접속 시 입력, 쿠키 저장) 없으면 모든 API 거부 |
| 노트북 꺼짐 | 트립 시작 전 앱이 서버 상태 확인 → 응답 없으면 "서버 꺼짐" 표시 |
| 와이파이 끊김 | 트립 중 외부 API 연속 실패 시 재시도, 복구 후 즉시 상태 재계산 |

- 서버 코드는 특정 OS에 의존하지 않게 작성 (Windows/Linux 모두). 추후 무료 클라우드(Fly.io, Oracle Cloud 무료 VM 등)로 옮길 때 코드 변경 없음.

## 11. 디렉터리 구조
```
WakeUp/
├── server/
│   ├── src/
│   │   ├── api/          # HTTP 라우트 (노선 검색, 트립, 구독)
│   │   ├── providers/    # TAGO, 서울시 어댑터 (공통 인터페이스)
│   │   ├── trip/         # 상태머신, 판정 로직 (순수 함수, 테스트 대상)
│   │   ├── scheduler/    # 트립별 폴링 타이머
│   │   ├── push/         # Web Push 발송
│   │   └── db/           # SQLite 스키마, 마이그레이션
│   └── test/
├── web/
│   ├── src/              # 화면: 검색, 즐겨찾기, 트립 진행
│   ├── public/manifest.webmanifest
│   └── sw.ts             # 서비스워커 (푸시 수신)
└── docs/
```
- 서버가 `web/` 빌드 결과를 정적 파일로 함께 제공 → 주소 하나로 운영.

## 13. 테스트
- 단위: 판정 로직에 기록된 버스위치 응답 시퀀스 주입 (정상, 정류장 건너뜀, 차량 사라짐, 갱신 지연, 몰려 다니는 버스).
- 통합: TAGO 목 서버로 트립 전체 흐름 재생.
- 실기기: iPhone 홈 화면 앱으로 잠금 상태 푸시 수신, 실제 탑승 테스트.
